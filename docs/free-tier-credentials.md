# Free-Tier Credential Setup

This guide is for running the free-provider SENTINEL path:

- Prometheus for metrics.
- Loki for logs.
- Generic HTTP webhooks for alerts.
- Discord webhooks for notifications.
- GitHub for repository evidence.
- A local `kind` Kubernetes cluster for deployment evidence and rollback proof.

Leave Datadog, PagerDuty, and Slack credentials blank when proving the free path. The free demo and free E2E gates reject paid-provider credentials by default.

## Required Values

| Variable | Source | Notes |
| --- | --- | --- |
| `SENTINEL_API_TOKEN` | Generate locally | SENTINEL's own bearer token for protected operator endpoints. This is not issued by a third party. |
| `PROMETHEUS_URL` | Docker Compose | Defaults to `http://prometheus:9090` inside Compose. |
| `LOKI_URL` | Docker Compose | Defaults to `http://loki:3100` inside Compose. |
| `GITHUB_TOKEN` | GitHub personal access token or `gh auth token` | Used for commits, pull requests, deployments, and repository contents. Keep `SENTINEL_GITHUB_WRITE_ENABLED=false` unless you intentionally want issue or runbook writes. |
| `GITHUB_OWNER` | GitHub | Repository owner or organization. |
| `GITHUB_REPO` | GitHub | Repository name. |
| `DISCORD_WEBHOOK_URL` | Discord channel webhook | Must look like `https://discord.com/api/webhooks/...`. |
| `SENTINEL_APPROVER_ID` | Local operator value | Any stable id for the human approver in the generic-webhook path, for example your username. |
| `HOST_KUBECONFIG` | Local machine | Host kubeconfig for `kind` setup and verification. |
| `CONTAINER_KUBECONFIG` | Generated by SENTINEL script | Container-safe kubeconfig mounted into Docker Compose. |
| `KUBECONFIG` | Docker Compose | Inside the container this should be `/root/.kube/config`. |

Generate `SENTINEL_API_TOKEN` locally:

```bash
python3 - <<'PY'
import secrets
print(secrets.token_hex(32))
PY
```

Bootstrap a free-tier `.env` skeleton without printing your GitHub token:

```bash
python3 scripts/bootstrap_free_tier_env.py \
  --github-token-from-gh-cli \
  --github-owner <owner> \
  --github-repo <repo>
```

Configure Discord with the hidden prompt so the full webhook URL is not written to shell history:

```bash
python3 scripts/configure_discord_webhook.py --test-post
```

Prepare local Kubernetes access for the Compose container:

```bash
python3 scripts/prepare_free_tier_host.py --install-kind --create-cluster --use-context
python3 scripts/prepare_container_kubeconfig.py --update-env-file .env
```

Check readiness before posting any alert:

```bash
python3 scripts/check_free_tier_readiness.py
docker compose up --build
python3 scripts/check_free_tier_readiness.py --check-receiver
```

Before `DISCORD_WEBHOOK_URL` is configured, `docker compose ps` may show the `sentinel` service as unhealthy because the container healthcheck calls authenticated `/ready/live`, and production readiness fails closed until a real notification provider is available. In that state Prometheus, Loki, Postgres, Redis, and the FastAPI receiver can still be running; the expected readiness blocker is `DISCORD_WEBHOOK_URL`. If `/ready` also lists `SLACK_BOT_TOKEN`, that means SENTINEL needs either Slack or Discord notification credentials. For the free proof, set Discord and leave Slack blank.

Run and audit the free demo:

```bash
python3 scripts/run_free_tier_sentinel_demo.py FREE-DEMO-001 \
  --base-url http://localhost:8000 \
  --summary-output .sentinel/free-tier-demo-summary.json

python3 scripts/audit_free_tier_goal.py \
  --demo-summary .sentinel/free-tier-demo-summary.json
```

## Additional Cloud Values To Leave Blank

Leave these unset for the free-provider proof:

- `DD_API_KEY`, `DD_APP_KEY`, `DD_OAUTH_TOKEN`, `DD_CLIENT_ID`, `DD_CLIENT_SECRET`
- `PAGERDUTY_API_KEY`, `PAGERDUTY_REQUESTER_EMAIL`, `PAGERDUTY_WEBHOOK_SECRET`
- `SLACK_BOT_TOKEN`, `SLACK_CHANNEL_ID`, `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`

SENTINEL still contains those provider surfaces. Treat Datadog, PagerDuty, and Slack as additional integrations unless they are configured and proven with real credentials in the target environment.

## Token Safety

- Do not commit `.env`.
- Keep `SENTINEL_GITHUB_WRITE_ENABLED=false` unless you want SENTINEL to mutate GitHub issues or runbook files.
- Rotate `SENTINEL_API_TOKEN`, `GITHUB_TOKEN`, and `DISCORD_WEBHOOK_URL` if they are pasted into logs or chat.
